# ADR-042: Механизм возврата платежей (Refund Saga Orchestration)

**Статус:** Принято  
**Дата:** 2026-09-19  
**Контекст:** Биллинг и процессинг платежей ООО «Ромашка»  
**Участники:** Архитектурный комитет, Core Team  

---

## 1. Контекст и проблема
При оформлении клиентом возврата средств за приобретённый товар или услугу требуется согласованное выполнение операций в нескольких независимых распределённых сервисах:
1. `order-service` — проверка права на возврат, статуса оплаты и сроков обращения.
2. `billing-service` / Внешний банковский эквайер — проведение обратной транзакции (RRN, Authorize reversal).
3. `accounting-service` (Главная книга / Ledger) — сторнирование бухгалтерских проводок, корректировка балансов.
4. `nats-jetstream` — нотификация смежных систем через Event Mesh (`orders.v1.refund`).
5. `notification-service` — отправка электронного чека возврата и SMS/Push клиенту.

Применение распределённых двухфазных блокировок (2PC) недопустимо из-за высоких задержек внешних банковских API и риска блокировки ресурсов.

---

## 2. Принятое решение
Реализован паттерн **Saga Orchestrator** с компенсационными транзакциями:
- Каждый шаг возврата описывается моделью `SagaStepDetail` со статусами: `PENDING`, `RUNNING`, `COMPLETED`, `FAILED`, `COMPENSATED`.
- Управление состоянием инкапсулировано в агрегате `RefundSaga` (домен `billing`).
- При успешном завершении саги оркестратор публикует событие `RefundSagaCompletedEvent` в `DomainEventBus` и NATS JetStream subject `orders.v1.refund` (ADR-043).
- В случае сбоя шага инициируется компенсационная цепочка (reversal).

---

## 3. Последствия
### Положительные:
- Отсутствие блокировок между микросервисами при задержках эквайринга.
- Полная наблюдаемость прогресса через UI пульта МИРОВИЗОР и WebSocket-стриминг.
- Гарантия доставки событий At-Least-Once в NATS JetStream с сохранением идемпотентности по ключу `orderId` и субмиллисекундной задержкой (< 1 мс).

### Отрицательные:
- Согласованность данных в конечном счёте (Eventual Consistency).
- Необходимость реализации явных компенсирующих операций для каждого шага.
